# Reality SNI Scanner

[English](README.md)

این ابزار به شما کمک می‌کند دامنه‌های مناسب برای `SNI` و `DEST` در تنظیمات
Xray Reality را پیدا کنید. خودش فهرستی از دامنه‌ها می‌سازد، به هرکدام اتصال
TLS واقعی می‌زند و گزینه‌های مناسب‌تر را بر اساس نتیجه و سرعت مرتب می‌کند.

## شروع سریع

فقط به Node.js نسخه 22.6 یا جدیدتر نیاز دارید. نصب npm لازم نیست.

```powershell
node run.js
```

برنامه به‌صورت پیش‌فرض 400 دامنه را بررسی می‌کند، نتیجه‌های مناسب را در ترمینال
نمایش می‌دهد و گزارش کامل را در فایل `results.json` ذخیره می‌کند.

نمونه خروجی نهایی:

```text
Best pick: example.com
Use in your Reality config as both SNI and DEST, e.g.:
  "dest": "example.com:443",
  "serverNames": ["example.com"]
```

## این اسکن دقیقاً چه چیزی را بررسی می‌کند؟

برای هر دامنه، برنامه بررسی می‌کند که آیا اتصال TLS برقرار می‌شود، TLS 1.3
دارد، HTTP/2 را پشتیبانی می‌کند و اتصال چقدر طول می‌کشد. به‌صورت پیش‌فرض TLS
1.3 و HTTP/2 لازم هستند.

اسکن را بدون VPN یا پراکسی اجرا کنید تا نتیجه مسیر واقعی اینترنت شما را نشان
دهد، نه مسیر VPN را.

### نکته بسیار مهم درباره VPS

اگر اسکن را روی لپ‌تاپ یا کامپیوتر خود اجرا کنید، فقط این مسیر آزمایش می‌شود:

```text
کامپیوتر شما → دامنه
```

اما Reality از سرور Xray به `DEST` وصل می‌شود:

```text
سرور Xray شما → دامنه
```

ممکن است دامنه‌ای روی کامپیوتر شما سریع باشد، ولی از VPS کند یا غیرقابل‌دسترسی
باشد. بعد از انتخاب چند گزینه، همین پروژه را روی VPS کپی کنید و همان فرمان را
آنجا هم اجرا کنید. نتیجه VPS باید مبنای انتخاب نهایی `DEST` باشد.

## فرمان‌های کاربردی

نمایش 50 نتیجه برتر:

```powershell
node run.js --top 50
```

بررسی دامنه‌های بیشتر و نمایش 50 گزینه اول:

```powershell
node run.js --candidates 1000 --top 50
```

ذخیره نتیجه در فایل دلخواه:

```powershell
node run.js --out my-results.json
```

## پیدا کردن دامنه از شبکه نزدیک VPS

اگر محدوده شبکه سرور خود را می‌دانید، می‌توانید دامنه‌هایی را هم که در آن محدوده
پیدا می‌شوند بررسی کنید:

```powershell
node run.js --neighbors --prefix 168.222.43.0/24
```

`168.222.43.0/24` فقط یک مثال است؛ آن را با CIDR واقعی سرور خود جایگزین کنید.
می‌توانید به‌جای CIDR، IP سرور را بدهید تا برنامه تلاش کند محدوده را پیدا کند:

```powershell
node run.js --neighbors --target 203.0.113.10
```

## پیدا کردن زیر‌دامنه‌های واقعی از Certificate Transparency

گزینه `--ct` در گزارش‌های عمومی Certificate Transparency به دنبال زیر‌دامنه‌های
واقعی شرکت‌های شناخته‌شده می‌گردد. این کار ممکن است کمی طول بکشد:

```powershell
node run.js --ct
```

برای ترکیب همه روش‌ها:

```powershell
node run.js --neighbors --prefix 168.222.43.0/24 --ct
```

## مراحل اسکن

اسکن در سه مرحله اجرا می‌شود:

**مرحله ۱ — تست سریع TLS:** برای هر دامنه اتصال TLS واقعی باز می‌شود و بررسی
می‌شود که TLS 1.3، HTTP/2 و گواهی معتبر دارد یا نه.

**مرحله ۱.۵ — کشف زیر‌دامنه (اختیاری):** کشف زیر‌دامنه هم‌زمان با مرحله ۱ و در
پس‌زمینه شروع می‌شود و برنامه دامنه‌های برتر را جست‌وجو می‌کند تا زیر‌دامنه‌های
آن‌ها را پیدا کند. مثلاً `www.google.com` → `accounts.google.com`,
`mail.google.com`. هر زیر‌دامنه با همان تست TLS بررسی شده و نتایج با مرحله ۱
ترکیب می‌شوند.

کشف زیر‌دامنه یک زنجیره جایگزینی دارد که همه آن در یک بودجه زمانی (`--ct-timeout`،
پیش‌فرض ۱۰ ثانیه) اجرا می‌شود: **crt.sh → Cert Spotter → جست‌وجوی DNS
(brute-force)**. اگر سرویسی در دسترس نباشد یا پاسخی ندهد، سرویس بعدی به‌صورت
خودکار امتحان می‌شود و سرویسِ ناموفق برای همین اجرا کنار گذاشته می‌شود. هر چیزی
که پیدا شود به مدت ۷ روز در `ct-cache.json` کنار `results.json` ذخیره می‌شود،
بنابراین اجرای بعدی برای همان دامنه‌ها اصلاً به شبکه نیاز ندارد
(`--ct-refresh` حافظه نهان را نادیده می‌گیرد و `--no-ct` کل مرحله ۱.۵ را رد
می‌کند). چون کشف هم‌زمان با مرحله ۱ انجام می‌شود، پیام‌های آن در حافظه نگه
داشته می‌شوند و بعد از نوشته‌شدن `results.json` و زیر سرفصل `--- stage 1.5 ---`
چاپ می‌شوند و در عنوان جدول
مرحله ۱.۵ یادداشت `[sources: ...]` نشان می‌دهد هر سرویس دقیقاً چه چیزی دریافت
کرده است (شامل `cached` برای نتایج خوانده‌شده از حافظه نهان).

> [!NOTE]
> crt.sh سرویس رایگان مشترکی با آپ‌تایم ضعیف است — به همین دلیل فقط *اولین*
> سرویس در زنجیره است. اگر همه سرویس‌ها از کار بیفتند، مرحله ۱.۵ دلایل را
> گزارش کرده و اجرا با نتایج مرحله ۱ و ۲ ادامه پیدا می‌کند.

**مرحله ۲ — تست واقعی تونل Reality:** بهترین گزینه‌ها با یک تونل Xray Reality
واقعی آزمایش می‌شوند و سرعت آپلود اندازه‌گیری می‌شود.

## راهنمای ساده گزینه‌ها

- `--candidates <n>` — تعداد دامنه‌های پیش‌فرض که بررسی می‌شوند؛ پیش‌فرض: `400`.
- `--top <n>` — تعداد نتیجه‌هایی که در ترمینال نمایش داده می‌شوند و سقف تعداد
  کاندیداهای مرحله ۲؛ پیش‌فرض: `15`.
- `--reality-test <n>` — تعداد کاندیداهای برتر که با تونل واقعی دوباره تست
  می‌شوند؛ پیش‌فرض: `min(10, --top)`؛ مقدار `0` این مرحله را غیرفعال می‌کند.
- `--concurrency <n>` — تعداد اتصال‌های هم‌زمان؛ پیش‌فرض: `40`.
- `--timeout <ms>` — حداکثر زمان هر اتصال به میلی‌ثانیه؛ پیش‌فرض: `4000`.
- `--out <file>` — نام فایل گزارش کامل؛ پیش‌فرض: `results.json`.
- `--neighbors` — جست‌وجوی دامنه از طریق reverse DNS در شبکه نزدیک سرور.
- `--target <ip>` — IP سرور برای پیدا کردن خودکار محدوده شبکه.
- `--prefix <cidr>` — محدوده شبکه را مستقیم وارد می‌کند؛ مانند `203.0.113.0/24`.
- `--sample <n>` — تعداد IPهایی که در آن محدوده بررسی می‌شوند؛ پیش‌فرض: `200`.
- `--ct` — جست‌وجوی زیر‌دامنه‌ها در Certificate Transparency.
- `--ct-limit <n>` — حداکثر دامنه دریافت‌شده از CT؛ پیش‌فرض: `300`.
- `--ct-timeout <ms>` — بودجه کل زمانی هر مرحله کشف CT که بین همه سرویس‌ها،
  تلاش‌های مجدد و جایگزینی‌ها تقسیم می‌شود؛ پیش‌فرض: `10000`.
- `--ct-source <name>` — سرویس مجاز برای کشف؛ پیش‌فرض: `auto`
  (crt.sh → Cert Spotter → جست‌وجوی DNS)؛ حالت‌های دیگر: `crtsh`، `certspotter`، `dns`.
- `--ct-refresh` — فایل `ct-cache.json` را نادیده گرفته و همه چیز را دوباره می‌گیرد.
- `--no-ct` — کل مرحله ۱.۵ (کشف زیر‌دامنه) را رد می‌کند.
- `--remote` — تلاش برای دریافت فهرست تازه دامنه‌ها از اینترنت؛ در صورت خطا از فهرست داخلی استفاده می‌شود.
- `--port <n>` — پورت اتصال؛ پیش‌فرض: `443`.
- `--no-require-h2` — HTTP/2 را اجباری نمی‌کند.
- `--no-require-tls13` — TLS 1.3 را اجباری نمی‌کند.
- `--require-authorized` — فقط گواهی‌هایی را قبول می‌کند که زنجیره معتبر عمومی دارند.
- `--verbose` (یا `-v`) — پیام‌های `[~]` عیب‌یابی را هم نشان می‌دهد (لاگ کامل
  Xray در مرحله ۲)؛ متغیر محیطی `REALITY_DEBUG_LOG=1` هم همین کار را می‌کند.
- `--quiet` (یا `-q`) — فقط خطاهای `[x]` را چاپ می‌کند؛ جدول‌های
  stdout دست‌نخورده می‌مانند.
- `--help` — فهرست کامل گزینه‌ها را نشان می‌دهد.

همه پیام‌های انسانی در **stderr** می‌روند و **stdout** فقط جدول‌ها را دارد،
بنابراین `node run.js > scan.txt` فقط جدول‌ها را ذخیره می‌کند. هر خط با یک
نشانگر سطح و نام مرحله شروع می‌شود:

| نشانگر | معنا |
| --- | --- |
| `[i]` | اطلاعات — کاری که الان انجام می‌شود |
| `[+]` | موفقیت — کاری درست تمام شد |
| `[!]` | هشدار — چیزی خطا داد ولی اجرا ادامه دارد |
| `[x]` | خطا — چیزی خطا داد و اجرا متوقف یا محدود شد |
| `[~]` | عیب‌یابی — فقط با `--verbose` |

شروع هر مرحله با سرفصل `--- stage N: ... ---` اعلام می‌شود.

## خواندن نتیجه‌ها

در خروجی، `ms` زمان اتصال است؛ کمتر معمولاً بهتر است. ستون `authorized` نشان
می‌دهد گواهی دامنه از دید Node.js معتبر عمومی بوده یا نه. برنامه به‌صورت پیش‌فرض
این مورد را فقط گزارش می‌کند، نه اینکه الزاماً دامنه را رد کند.

فایل `results.json` تمام نتیجه‌ها، از جمله دامنه‌های ناموفق و دلیل خطا را نگه
می‌دارد.

## خطاهای رایج

- **هیچ نتیجه‌ای پیدا نشد:** تعداد دامنه‌ها را بیشتر کنید یا برای آزمایش،
  `--no-require-h2` را اضافه کنید.
- **اتصال‌ها timeout می‌شوند:** اتصال اینترنت، فایروال، DNS یا زمان `--timeout`
  را بررسی کنید.
- **خطاهای سرویس‌های CT یا "none of the ... subdomains passed":** سرویس‌های CT
  ممکن است از دسترس خارج شوند (به‌ویژه crt.sh) و گزارش‌ها شامل زیر‌دامنه‌های
  قدیمی‌ای هستند که دیگر وجود ندارند. کشف به‌صورت خودکار از crt.sh به Cert
  Spotter و سپس به جست‌وجوی DNS جایگزین می‌شود؛ خراب‌بودن یک سرویس فقط زمان
  صرف می‌کند. اگر *همه* سرویس‌ها از کار بیفتند، اجرا همچنان با نتایج مرحله ۱ و ۲
  تمام شده و دلیل هر سرویس در پیام‌ها می‌آید. بعداً دوباره تلاش کنید یا وقتی
  سرویس‌ها سالم‌اند `--ct-refresh` بزنید.
- **Node.js خیلی قدیمی است:** Node.js را به نسخه 22.6 یا جدیدتر ارتقا دهید.

برای مشاهده همه گزینه‌ها همیشه می‌توانید این فرمان را اجرا کنید:

```powershell
node run.js --help
```
